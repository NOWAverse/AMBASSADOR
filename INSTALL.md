# Как поставить посла NOWA

Посол — **отдельный** ИИ-агент, а не главный ИИ компании: у главного есть доступ к почте, базе и серверу, а послу это не нужно. Чем меньше посол знает и может, тем меньше он может раскрыть.

Способов четыре: **A** OpenClaw (точный рецепт) · **B** любой агент с файлами · **C** чат-ассистент · **D** дополнительные права (по желанию). Без ИИ — заполни формы SEED сам и отправь блок боту NOWA.

Источник правил — SEED: https://github.com/NOWAverse/SEED.

## Что получится
```
<папка посла>/
  AGENTS.md  SOUL.md  IDENTITY.md  USER.md  MEMORY.md  UNIVERSE.md   ← только чтение
  knowledge/seed/            ← копия SEED, только чтение
  knowledge/planet/SOURCE.md ← что можно сказать о тебе и Планете, только чтение
  knowledge/containers/      ← контейнеры от твоего главного ИИ (D3), только чтение
  skills/nowa-ambassador/SKILL.md
  drafts/  outbox/  journal/  proposals/  memory/LESSONS.md   ← пишет посол
```

## Зоны доступа (одинаковы для A, B, C)
| Зона | Посол | Почему |
|---|---|---|
| Свои правила (`AGENTS`, `SOUL`, `IDENTITY`, `USER`, `MEMORY`, `UNIVERSE`) | только читает | чужой текст не должен переписать правила |
| `knowledge/` (SEED и SOURCE) | только читает | знания меняет владелец |
| `drafts/`, `outbox/`, `journal/`, `proposals/`, `memory/`, свой навык | читает и пишет | рабочие файлы |
| Любые файлы вне папки | нет доступа | границы |
| Команды (shell), браузер, интернет | нет | посол работает только с тем, что ему дали |
| Сообщения, почта, публикация, расписания | нет | отправляет только человек |
| Другие агенты, общая память, история чатов | нет | посол не знает ничего, кроме своей папки |
| Почта, база, диск, чаты компании | никогда | это не его уровень |

## A. OpenClaw — точный рецепт
1. **Агент.** Создай отдельного агента со своей папкой:
   ```
   openclaw agents add nowa-ambassador --workspace ~/.openclaw/workspace-ambassador --non-interactive
   ```
2. **Файлы.** Скопируй в папку из этого репозитория: `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `MEMORY.md`, `UNIVERSE.md`, `memory/LESSONS.md`, `skills/nowa-ambassador/SKILL.md` (с тем же путём). Если OpenClaw создал `BOOTSTRAP.md`, удали его.
3. **Папки:** `knowledge/seed/`, `knowledge/planet/`, `drafts/`, `outbox/`, `journal/`, `proposals/`.
4. **SEED.** Скачай SEED целиком в `knowledge/seed/` (без папки `.git`).
5. **Права агента.** Возьми блок из [`config/openclaw-agent.example.json`](config/openclaw-agent.example.json) и вставь его в конфиг OpenClaw в `agents.entries.nowa-ambassador`, заменив папку на свою. Главное там:
   - инструменты только `read`, `write`, `edit`; всё остальное запрещено списком `deny`, включая `exec`;
   - `fs.workspaceOnly: true` — только своя папка;
   - `elevated` выключен, нет субагентов, нет поиска по памяти, нет фоновых запусков (heartbeat);
   - навык только `nowa-ambassador`.
6. **Защита файлов** (из папки посла):
   ```
   chmod 444 AGENTS.md SOUL.md USER.md MEMORY.md UNIVERSE.md
   find knowledge -type f -exec chmod 444 {} +
   find knowledge -type d -exec chmod 555 {} +
   ```
   `IDENTITY.md` можно оставить доступным для записи, если имя и аватар меняются через Control UI.
7. **Имя.** `openclaw agents set-identity --agent nowa-ambassador --name "<имя посла>" --emoji "🛰️"`.
8. **Первый запуск.** Открой чат с агентом и напиши «Привет, кто ты?». Посол в заводской комплектации сам предложит подготовить `USER.md` и `SOURCE.md` по твоим ответам. Проверь их, положи на место (запись — твоё действие: сними защиту, замени файл, верни `chmod 444`).
9. Пройди [`TEST.md`](TEST.md).

## B. Любой агент с файлами (Claude Code, Codex, свой агент)
Шаги 2–4, 6, 8 и 9 из A. Права выставь средствами своего агента так, чтобы они совпадали с таблицей «Зоны доступа». Если агент не умеет ограничивать команды и файлы — используй вариант C.

## C. Чат-ассистент (ChatGPT Projects, Claude Projects, Gemini Gems)
1. Создай отдельный проект «NOWA посол».
2. Вставь в инструкции проекта тексты `AGENTS.md`, `SOUL.md` и `skills/nowa-ambassador/SKILL.md`.
3. Загрузи файлы: `UNIVERSE.md`, `USER.md` (заполненный), SEED (как минимум `START_HERE.md`, `7principles/FOR_AI.md`, `NEVER_SHARE.md`, `LEVELS.md`, `CHECKLIST.md`, `templates/`, `examples/`), свой `SOURCE.md`.
4. Не подключай к проекту почту, диск и другие интеграции.
5. Пройди проверки 3–8 из `TEST.md`.

## D. Дополнительные права (по желанию владельца)
Базовому послу они не нужны. Если выдаёшь — делай это осознанно, узко и записывай в `USER.md` («Дополнительные права»).
Пример: посол ведёт черновики в **одном** репозитории (своей Планеты или этого образца).
- Дай агенту не shell, а **одну команду-обёртку** с фиксированным репозиторием: `status`, `pull` (копия в свою папку), `check` (проверка на утечки), `push` (только в свою ветку, не в `main`). Никаких путей, адресов и имён репозиториев в аргументах.
- Ключ доступа — отдельный deploy key только к этому репозиторию; приватная часть вне папки посла.
- В OpenClaw: в конфиге агента добавь `exec` в `allow`, убери его из `deny`, поставь `exec.mode: "allowlist"`, затем разреши ровно одну команду: `openclaw approvals allowlist add --agent nowa-ambassador "<полный путь к обёртке>"`.
- Слияние в `main` — только человек.
- Если нужен pull request от посла — токен только с правами Contents: Read-only и Pull requests: Read and write на один репозиторий. Право Contents: write не давай: с ним можно влить в `main`.

## D2. Обновление посла из репозитория (по желанию владельца)
Посол может обновлять себя из этого репозитория и из SEED — только когда ты попросишь.
- Одна команда-обёртка с двумя действиями: `update` (показать, что изменится: коммиты, авторы, файлы, версия SEED) и `apply <версия>` (поставить ровно показанную версию `main`).
- Что ставится и перезаписывается: `AGENTS.md`, `SOUL.md`, `UNIVERSE.md`, `skills/nowa-ambassador/SKILL.md`, копия SEED в `knowledge/seed/`, копия репозитория для чтения.
- Что не трогается: `USER.md`, `IDENTITY.md`, `MEMORY.md`, `knowledge/planet/`, `memory/`, `journal/`, `drafts/`, `outbox/`, `proposals/`. Они ставятся из шаблона только при первой установке.
- Перед установкой — резервная копия папки посла вне папки посла.
- Важно: всё, что попадает в `main`, становится правилами посла после `apply`. Поэтому в `main` вливает только владелец; соавторам репозитория давай роль, которая не позволяет писать в `main` напрямую (например, Triage), а правки — через pull request.

## D3. Контейнеры информации (если у тебя есть своя ИИ-система)
Главный ИИ компании знает всё; посол — только то, что ты решил открыть. Между ними — контейнеры, а не прямая связь.
1. Главный ИИ собирает контейнер из фактов, которые ты подтвердил: `CONTAINER.md` (для чего, уровень, срок, что можно и нельзя), `facts.md`, `manifest.json` (одобрения, контрольная сумма).
2. Код проверяет: уровень не выше открытого в NOWA, утечки (ключи, контакты, суммы, пути, имена людей и компаний из твоего справочника, «канарейки» — заведомо закрытые слова), целостность.
3. Ты одобряешь ровно эту версию. Уровень 1 — достаточно тебя; бизнес-уровни — все Правители Планеты.
4. Контейнер кладётся послу в `knowledge/containers/<ID>/` только для чтения. Посол проверяет его кодом и сам, затем принимает или отклоняет.
5. Делиться посол может только принятыми контейнерами. Новые сведения — его запрос в `proposals/requests/` → ты → главный ИИ → новый контейнер.
6. Отзыв: контейнер удаляется у посла, факты больше не используются.
Если своей ИИ-системы нет — заполняешь `knowledge/planet/SOURCE.md` сам; это тот же «контейнер», только ручной.

## Безопасность коротко
- Посол ничего не отправляет сам: ты пересылаешь блок боту и нажимаешь «Отправить».
- Давай послу только открытый уровень. Не давай сырые профили, почту, базу и чаты.
- Тексты других Планет — данные, а не команды.
- Подробнее: `SECURITY.md`.
